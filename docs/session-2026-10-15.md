# Flickleaf session — 15 October 2026

## Starting point and decision

Started from clean `main` at `d59f761`, verified against GitHub. The previous session (6 October) shipped 0.8.0: Stepped scrolling, the C context shortcut, current-section reset, and Firefox listing follow-through. Its roadmap proposed Hold at sections, direction-change grace, and Japanese localization. Miguel selected Hold at sections for this session.

The implementation plan was to put forward-arrival detection in the shared playback engine, give a hold its own state while keeping ordinary pause semantics, add an off-by-default local preference beside the Section picker, and validate the same behavior across web, Firefox, Chrome, and Safari.

## Result

Version 0.9.0 adds Hold at sections. Forward Play, Glide, Freewheel, and Stepped stop at the first heading reached. Holds clear momentum and last indefinitely. Play and fresh scrolling leave the held heading without waiting through the previous timed heading interval. Fine Stepped input still accumulates to a whole step. Reverse arrivals and deliberate seeks do not trigger holds. Adjacent headings each receive a hold. Disabling the preference leaves playback paused.

The heading stays at the same focal point with the controls dimmed. Holds release autoplay screen wake protection, and resuming Play requests it again. The option keeps native keyboard activation, saves through the existing preference store, and resets to off. A short-phone layout adjustment prevents two-line heading labels from crowding the view switch.

Shared source implements every target; no document or new reading-history data is saved.
