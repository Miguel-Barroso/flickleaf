# Flickleaf roadmap

Recorded from the agreed plan on 25 September 2026.

## Current batch: make everyday use dependable

- Remember pace, minimum/maximum limits, scroll mode, and theme locally, with a clear reset. Never save document text or reading history as a side effect.
- Validate changes automatically and produce versioned Firefox, Chrome, and Safari development packages with release notes.
- Prepare Firefox Add-ons listing, privacy statements, reproducible source, and reviewer notes. Actual store submission and signing remain a separate release step.

## Next

1. Publish Firefox, then Chrome store releases for easy installation and updates. Sign Safari and test it on physical Apple devices before distribution.
2. Offer optional local reading-position resume. Saving document text must be a separate explicit choice, with deletion controls.
3. Improve PDF cleanup: repeated headers/footers, page numbers, and line-break hyphenation, with a preview before applying changes.
4. Add a normal paragraph view that preserves the reading position when switching to or from single-word playback.
5. Maintain a real-device checklist covering iPhone, Android, and Safari.
6. Improve contributor onboarding with a short demo, screenshots, issue templates, and clear licensing (MIT selected for this batch).

## Guardrails

All reader changes reach web, Firefox, Chrome, and Safari through shared source. Keep text and PDF processing local, pace settings directly visible, and headings at the same quiet reading focal point. Do not claim comprehension or speed benefits that have not been demonstrated.
